Backend • Versiuni & Securitate

Ecosistemul PHP în Prezent

De ce versiunea de PHP și structurarea codului sunt critice pentru performanță

Statutul Versiunilor PHP

  • PHP 8.5 este versiunea stabilă recomandată în producție.
  • PHP 8.6 aduce aplicarea parțială a funcțiilor, clamp() și tip nativ Time\Duration.
  • PHP 8.1 & mai vechi: End of Life (fără update-uri de securitate).
  • Securitate critică: patch-uri RCE aplicate recent (versiunile 8.5.12, 8.4.27, 8.3.36).
  • Proiectul nostru: Rulează pe PHP 8.3/8.4+, cu escapare strictă prin e() și zero erori de sintaxă.

Arhitectura Modulară (DRY) a Proiectului

// Încarcă configurarea & componentele partajate require_once __DIR__ . '/includes/config.php'; require_once __DIR__ . '/data-products.php'; // Antet comun cu Speculation Rules & View Transitions require __DIR__ . '/includes/head.php'; require __DIR__ . '/includes/header.php'; // ... Conținut unic pagină ... require __DIR__ . '/includes/footer.php';

Fiecare pagină include config.php, head.php, header.php și footer.php. Fără cod duplicat.

Ce spui la acest slide:

„Pe partea de backend, proiectul respectă cerințele PHP moderne. Versiunile vechi sub 8.2 nu mai primesc suport, iar noi am structurat codul modular, respectând principiul DRY (Don't Repeat Yourself). Am creat un folder includes/ care găzduiește configurarea globală, head-ul cu meta-etichete, navbar-ul și dialogul de lightbox. Astfel, orice modificare de brand sau logică se propagă instant pe toate paginile.”

Frontend • Semantică HTML5 & APIs

HTML Semantic & Speculation Rules

Structură curată pentru Googlebot și încărcare la 0 milisecunde

Ierarhia Semantică HTML5

  • <header> și <nav> pentru identificare și meniu accesibil.
  • Un singur <main> vizibil per pagină — cerință strictă Google.
  • <article> pentru produsul de sine stătător.
  • Ierarhie strictă fără salturi: <h1> unic → <h2> secțiuni → <h3> specificații.
  • <dialog> nativ HTML5 pentru lightbox (accesibil tastatură, Escape automat).

Speculation Rules API (Chrome)

<script type="speculationrules"> { "prerender": [ { "source": "list", "urls": ["disc-frana-brembo.php", "kit-ambreiaj-sachs.php"] } ], "prefetch": [ { "source": "list", "urls": ["disc-frana-brembo.php", "kit-ambreiaj-sachs.php"] } ] } </script>

Browserul pre-randează în memorie paginile de produs înainte ca utilizatorul să dea click. Când dă click, pagina apare instantaneu (0ms).

Ce spui la acest slide:

„Google penalizează paginile construite din simple div-uri generice. Noi am folosit etichete semantice native: header, nav, main, article, section, aside și footer, cu un singur H1 per pagină. În plus, am implementat cel mai nou API din Chrome — Speculation Rules API. Când ești pe catalog, browserul randează în background paginile produselor. Când utilizatorul apasă pe produs, tranziția este de zero milisecunde.”

Performanță • Core Web Vitals

Optimizarea Imaginilor & Metrici Vitale

Cum eliminăm CLS-ul și optimizăm LCP-ul și INP-ul

Regula celor 3 Imagini & Zero CLS

  • 3 vederi tehnice per piesă: frontală, unghi ventilație/mecanism, profil cote tehnice.
  • Dimensiuni explicite width și height pe toate imaginile pentru a preveni saltul paginii (CLS = 0).
  • fetchpriority="high" pe imaginea principală din Hero (optimizare LCP - Largest Contentful Paint).
  • loading="lazy" și decoding="async" pe thumbnail-uri și produsele de mai jos.

Cele 3 Metrici Core Web Vitals (2026)

LCP (Largest Contentful Paint) < 1.2s

Timpul de afișare a celei mai mari imagini. Obținut prin preconnect și fetchpriority.

CLS (Cumulative Layout Shift) = 0.00

Pagina nu trepidează la încărcare datorită aspect-ratio: 4/3 definit în CSS.

INP (Interaction to Next Paint) < 50ms

A înlocuit vechiul FID. Interacțiunea la click pe galerie și căutare este instantanee.

Ce spui la acest slide:

„Pentru un magazin de piese auto, imaginile sunt cruciale. Am inclus 3 fotografii tehnice pentru fiecare produs: frontal, unghi și cote. Pentru a satisface standardul Core Web Vitals impus de Google, toate imaginile au lățime și înălțime declarate strict, prevenind deplasarea conținutului — scorul CLS fiind zero. Pe imaginea principală am folosit fetchpriority='high' pentru un LCP impecabil.”

Styling • CSS Modern 2026

CSS Modern: @layer, :has() & Nesting

Scriem CSS scalabil direct în browser, fără nevoie de SASS sau PostCSS

Funcționalități CSS Native Utilizate

  • Cascade Layers (@layer): împarte stilurile în reset, base, layout, components, utilities. Elimină conflictele de specificitate (fără !important).
  • Selectorul părinte :has(): permite stilizarea barei de căutare când inputul are focus:
    .ap-search-form:has(input:focus) .ap-search-icon { color: red; }
  • CSS Nesting nativ: scriem stiluri imbricate direct în CSS curat.
  • contain: layout pe cardurile produselor pentru a reduce costul de recalculare la hover.

Exemplu din Codul Nostru (style.css)

@layer reset, base, layout, components, utilities; @layer components { .ap-product-card { contain: layout; transition: transform var(--ap-transition); &:hover { transform: translateY(-5px); box-shadow: 0 16px 40px rgba(0,0,0,0.1); } } .ap-search-form:has(.ap-search-input:focus) .ap-search-icon { color: var(--ap-primary); } }
Ce spui la acest slide:

„La nivel de stilizare, am evitat dependențele grele. Am folosit cele mai noi capacități native din CSS: @layer pentru organizarea priorităților de cascadă, CSS Nesting nativ și puternicul selector :has(), care permite modificarea elementelor părinte în funcție de starea copiilor. Rezultatul este un CSS curat, ușor de întreținut și ultra-rapid.”

Tooling • Node.js & esbuild

Compresie Automată CSS + JS

Watch mode la salvare (CMD+S) cu reducere de peste 50% a dimensiunii

Cum funcționează build.js?

  • Construit cu Node.js și esbuild — cel mai rapid compilator din industrie (scris în Go).
  • Mod Watch (npm run watch): ascultă evenimentele sistemului de fișiere (fs.watch).
  • Debounce de 50ms: previne dubla compilare la salvare.
  • PHP detectează automat: dacă există style.min.css, îl servește direct în producție.

Rezultate Reale de Compresie

style.css → style.min.css -43.9%
22.07 KB → 12.37 KB (Timp: ~36ms)
script.js → script.min.js -52.0%
14.09 KB → 6.76 KB (Timp: ~4.4ms)
Ce spui la acest slide:

„Pentru fluxul de dezvoltare, am configurat un script în Node.js bazat pe esbuild. Rulând npm run watch, orice salvare prin Command+S sau Control+S declanșează recompilarea și minificarea instantanee a CSS-ului și JavaScript-ului în mai puțin de 10 milisecunde. Fișierul JavaScript a fost redus cu 52%, iar PHP servește automat fișierele .min dacă acestea există pe disc.”

Interactivitate • Căutare Inteligentă

Bara de Căutare Live Autocomplete

Căutare după brand, cod OEM, dimensiune și serie de șasiu (VIN)

Arhitectura Sistemului de Căutare

  • Sursă Unică de Adevăr: fișierul data-products.php oferă funcțiile get_all_autoparts() și search_autoparts($q).
  • Căutare Server-Side (PHP): pe index.php?s=brembo filtrează catalogul complet chiar dacă JS e oprit (accesibilitate maximă).
  • Căutare Client-Side (JS Live): interoghează api-search.php?q=... și afișează dropdown cu poze, coduri, preț și highlight galben.
  • Navigare completă din tastatură: Săgeată Jos / Sus • Enter pentru selectare • Escape pentru închidere.

Tehnici Avansate în script.js

  • Debounce de 100ms: nu trimite cereri inutile la fiecare literă tastată.
  • AbortController: anulează cererile HTTP precedente dacă utilizatorul continuă să tasteze (zero race-conditions).
  • XSS Protection: funcție dedicată escapeHtml() pentru a preveni atacurile prin injectare de cod în rezultate.
Ce spui la acest slide:

„Un magazin auto depinde de rapiditatea căutării după coduri sau dimensiuni. Am creat un sistem hibrid: căutare clasică server-side în PHP pentru indexare Google, completată de un autocomplete live în JavaScript. Folosim un debounce de 100 milisecunde și AbortController pentru a anula cererile vechi, oferind rezultate instantanee cu imagini, preț și suport complet pentru tastatură.”

SEO Tehnic • Date Structurate

Schema.org JSON-LD & Google Merchant

Cum comunicăm direct cu motoarele de căutare fără ambiguitate

Schemas Implementate în Proiect

  • Product Schema: name, image (3 imagini), sku, mpn, gtin13, brand.
  • Offer Schema: price, priceCurrency: RON, availability: InStock.
  • OfferShippingDetails & MerchantReturnPolicy: taxe livrare 0 RON și retur 30 zile.
  • AggregateRating & Review: recenzii semnate de experți RAR pentru stele aurii în Google Search (Rich Snippets).
  • BreadcrumbList: ierarhie vizuală în rezultatele căutării.
  • Organization & WebSite SearchAction: casetă de căutare direct în Google (Sitelinks Search Box).

Resurse Tehnice Create

  • sitemap.xml: include etichetele oficiale Google image:image, image:loc și image:caption.
  • feed.xml: Feed oficial Google Merchant Center RSS 2.0 cu namespace xmlns:g pentru Google Shopping.
  • IndexNow: protocol suportat pentru ping instantaneu către Bing și Yandex la adăugarea unei piese noi.
Ce spui la acest slide:

„SEO nu mai înseamnă doar cuvinte cheie repetate în pagină, ci date structurate JSON-LD. Am implementat schema completă de Produs recomandată de Google: preț, stoc, cod de bare GTIN, politică de retur și recenzii ale mecanicilor pentru Rich Snippets. În plus, am generat un feed XML pentru Google Merchant Center și un sitemap extins cu imagini.”

Inovație 2026 • GEO & AI Search

De la SEO clasic la SEO + GEO

Optimizare pentru a fi citat în Google AI Overviews, SearchGPT, Perplexity și Claude

Ce este GEO (Generative Engine Optimization)?

  • Modelele AI răspund direct în căutare (Zero-Click Searches). Scopul este să fim sursa citată în sinteză.
  • Direct Answer Box: plasat imediat sub H1 pe paginile produselor — oferă răspuns clar, dens și concis la ce este piesa, pe ce mașini se potrivește și cât costă.
  • Format ușor de extras: tabele HTML clare și liste neordonate (preferate de crawlerele LLM).
  • FAQ semantic integrat cu răspunsuri scurte și autoritare.

llms.txt & Politica robots.txt

  • llms.txt creat: fișierul propus ca standard pentru ghidarea modelelor de limbaj către datele verificate și specificațiile cheie.
  • robots.txt inteligent:
    • Permite boții de citare AI: GPTBot, PerplexityBot, ClaudeBot, Google-Extended.
    • Blochează capcanele de conținut duplicat: parametrii de sortare și fațetare (?sort=, ?filter=).
Ce spui la acest slide:

„Marea schimbare din 2026 este trecerea la GEO — Generative Engine Optimization. Când un utilizator întreabă ChatGPT sau Google AI dacă discurile Brembo de 312mm merg pe Golf 7, motorul AI caută pagini cu casete de răspuns direct. Noi am integrat un Direct Answer Box sub titlu, un fișier llms.txt și am configurat robots.txt să permită accesul crawlerelor generative pentru a ne asigura că suntem citați ca sursă.”
